# 2026-05-07 01:30 — run7: PS5 rejects 4K Remote Play (AvCap InitResult:-6)

## 1. What is going wrong

Session bring-up completes the entire negotiation chain (registration, ctrl, Senkusha RTT/MTU probe, takion v12 handshake, BANG) and then the PS5 immediately disconnects:

- Log line: `Remote disconnected from StreamConnection with reason "Nagare did not init! AvCap failed to initialize video: [InitResult:-6]"`
- Followed by: `StreamConnection didn't receive streaminfo`
- Final state: `StreamSession: quit reason=11` — `CHIAKI_QUIT_REASON_STREAM_CONNECTION_REMOTE_DISCONNECTED` ([`session.h:114`](../../../lib/include/chiaki/session.h)).
- Network is healthy: Senkusha RTT 3.5 ms avg, MTU 1454 both directions, BANG received cleanly.
- Our request shape (from log): `3840x2160 @60fps codec=h265` (SDR, not HDR — the user's persisted `settings.json` still has `.h265`; the new `.h265hdr` default applies only to fresh installs).

## 2. Why it is going wrong

The PS5 only supports **up to 1080p** for Remote Play streaming. We're requesting **2160p** (4K), the PS5 accepts the launch spec at the protocol level (BANG fires), then its internal video encoder (`Nagare`/`AvCap`) refuses to initialise and the server tears the connection down with `InitResult:-6`. Source: our [`AppSettings.swift`](../../ChiakiTV/Models/AppSettings.swift) defaults `resolution = .res2160p` and [`StreamSession.swift`](../../ChiakiTV/Services/Session/StreamSession.swift) passes `3840x2160` straight into `chiaki_tv_session_config_t.video_width/height`.

`video_profile_auto_downgrade=true` does not catch this: at [`ctrl.c:1442-1461`](../../../lib/src/ctrl.c) the only downgrade branches handle (a) `server_type == 0` (PS4) at 1080p → 720p, and (b) PS4/PS4-Pro requesting non-H264 → H264. **Server type 2 (PS5) requesting 2160p is not a downgrade case in upstream**, because upstream never lets the user pick >1080p in the first place.

## 3. How chiaki-ng handles it

Chiaki-ng's desktop UI caps resolution at 1080p:
- [`gui/src/settings.cpp:454`](../../../gui/src/settings.cpp): the resolution-preset table has only `{ CHIAKI_VIDEO_RESOLUTION_PRESET_1080p, "1080p" }` as the top entry.
- [`gui/src/settings.cpp:458`](../../../gui/src/settings.cpp): `resolution_default_ps5_local = CHIAKI_VIDEO_RESOLUTION_PRESET_1080p`.
- [`lib/src/session.c:92-122`](../../../lib/src/session.c): the preset table itself stops at 1080p (15 Mbps).

So upstream never tries 4K — the UI doesn't expose it.

## 4. How we differ from chiaki-ng

| | chiaki-ng desktop | tvOS port (today) |
|---|---|---|
| Max selectable resolution | 1080p (UI cap) | 2160p (`.res2160p` in `VideoResolution` enum) |
| Default resolution | 1080p | **2160p** ← causes the failure |
| Default bitrate | 15 000 kbps | 30 000 kbps (sized for 4K) |
| Default codec | H.265 | H.265 HDR |
| Auto-downgrade behaviour | Triggers for PS4@1080p only | Never triggers — `server_type == 2` falls through |

The chiaki-ng "Phase 2 — 4K60 HDR" target was built on a wrong premise. PS5 Remote Play does **not** stream 4K. The HDR work is still valid at 1080p (HDR10 metadata, BT.2020 PQ render path, AVDisplayCriteria) — only the resolution target needs correcting.

---

**Proposed fix (awaiting approval):** drop `AppSettings.resolution` default from `.res2160p` to `.res1080p`, and `bitrateKbps` from 30 000 to 15 000 (matching upstream's 1080p preset). Keep the `.res2160p` enum case so the UI can still expose it as an experimental opt-in, but document in `phases.md` and `decisions.md` that PS5 Remote Play caps at 1080p. Codec default `.h265hdr` stays — HDR @ 1080p60 is what the PS5 actually serves.
