# Run 1 — VideoDecoder double-free crash on first frame

Logs: [`2026-05-05-17-47-run1-logs.txt`](./2026-05-05-17-47-run1-logs.txt)

## 1. What is going wrong

Process aborts with `malloc: double free for ptr 0x1050a3e00` on the first
decoded frame. The session establishes cleanly through the full handshake —
registration, ctrl, Senkusha, Takion, BANG, audio header, video profile
selection, AudioPlayer started, `StreamSession: connected`, format
description rebuilt — and then immediately dies. Sequence in the log:

- `2026-05-05 17:47:45.744290` — `StreamSession: connected`
- `2026-05-05 17:47:45.762012` — `Switched to profile 0, resolution: 1920x1080`
- `2026-05-05 17:47:45.868318` — `VideoDecoder: rebuilt session (codec=h265 vps=24B sps=49B pps=7B)`
- `2026-05-05 17:47:45.868xxx` — `malloc: double free for ptr 0x1050a3e00`
  → `Debug session ended with code 9: killed`

Two malloc-error printouts back-to-back for the same pointer, then the
process is killed by signal 9 (SIGKILL via crash handler).

The handshake-level "Received presumably invalid Session Id … Ctrl set
fallback session Id …" notices in the log are a known PS5 quirk (chiaki-lib
already handles it via the fallback path) and are unrelated.

## 2. Why it is going wrong

Ownership-transfer bug in
[`tvos/ChiakiTV/Services/Video/VideoDecoder.swift:93-134`](../../ChiakiTV/Services/Video/VideoDecoder.swift).

The walker `walkAnnexB(...)` returns a struct holding a `malloc`'d AVCC
buffer. The decoder `defer`s `free(walked.avccBuffer)` for early-return
safety, then hands the same pointer to
`CMBlockBufferCreateWithMemoryBlock` with `blockAllocator: kCFAllocatorMalloc`
— i.e. CoreMedia takes ownership and will `free` on block release. To
prevent the `defer` from also freeing, the code tries to clear the field:

```swift
let walked = walkAnnexB(data, codec: codec)        // line 95: immutable
defer {
    if let buf = walked.avccBuffer { free(buf) }   // line 97: reads `walked`
}
…
guard blockStatus == noErr, let block = blockBuffer else { return false }
var walkedMut = walked                              // line 133: copy of struct
walkedMut.avccBuffer = nil                          // line 134: clears COPY
```

`walkedMut` is a separate value-type copy. The `defer` closes over the
original `walked`, whose `avccBuffer` is still the live pointer. On
function return CoreMedia later releases the block buffer and frees the
pointer (free #1), and the deferred call frees the same pointer (free #2)
— matching the abort message.

## 3. How chiaki-ng handles it

The desktop chiaki-ng decoder doesn't perform Annex-B → AVCC repacking
itself; the `videotoolbox` codepath at
[`gui/src/qmlbackend.cpp:videotoolbox`](../../../gui/src/qmlbackend.cpp)
hands frames to FFmpeg's `hw_videotoolbox_load`, which manages the buffer
lifecycle internally via `AVPacket`/`av_buffer_ref`. So there's no direct
chiaki-lib reference for "how upstream owns the AVCC buffer when feeding
`VTDecompressionSession` raw."

The closest in-tree reference is the sibling iOS port we explicitly model
this file on:
[`../../ps-remote-play/PSSwiftPlay/Services/Streaming/VideoDecoder.swift:613-732`](../../../../ps-remote-play/PSSwiftPlay/Services/Streaming/VideoDecoder.swift).

```swift
var walked = walkAnnexB(workingData)            // line 613: VAR, not let
defer {
    if let buf = walked.avccBuffer { free(buf) } // sees mutations via Swift's
}                                                // value-type-on-defer semantics
…
let blockStatus = CMBlockBufferCreateWithMemoryBlock(
    allocator: kCFAllocatorDefault,
    memoryBlock: avccBuffer,
    blockAllocator: kCFAllocatorMalloc,         // line 724: takes ownership
    …
)
guard blockStatus == noErr, let block = blockBuffer else { return nil }
walked.avccBuffer = nil                          // line 732: mutates the SAME var
```

The sibling declares `var walked` and mutates `walked.avccBuffer` in place.
`defer` captures `walked` by reference to the storage, so on the deferred
read the field is `nil` and `free` is skipped — single free, performed by
CoreMedia.

## 4. How we differ from chiaki-ng / sibling

Two-line delta from the sibling pattern in `VideoDecoder.swift`:

| | Sibling (correct) | tvOS port (buggy) |
|---|---|---|
| Walker binding | `var walked = walkAnnexB(…)` (line 613) | `let walked = walkAnnexB(…)` (line 95) |
| Post-transfer clear | `walked.avccBuffer = nil` (line 732) | `var walkedMut = walked` then `walkedMut.avccBuffer = nil` (lines 133-134) |

Because Swift `defer` closes over the storage of `walked`, mutating the
original `var` is visible from the deferred block; mutating a fresh copy
is not. Switching to `var walked` and dropping the `walkedMut` shim makes
the code match the sibling line-for-line.
